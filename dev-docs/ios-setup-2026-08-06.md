# iOS Setup — Steps for the Mac

`@capacitor/ios` is already in `frontend/package.json`, but `npx cap add ios` has never been run — no `frontend/ios/` directory exists yet in the repo on any machine. This is greenfield setup, not porting over something that already half-exists.

## Prerequisites

- Xcode (from the Mac App Store)
- CocoaPods (`sudo gem install cocoapods`, or `brew install cocoapods`)

## Steps

1. **Add the platform**
   ```
   cd frontend
   npx cap add ios
   ```
   This generates `frontend/ios/`.

2. **Regenerate icons/splash for iOS**
   `@capacitor/assets` is already a dependency — same tool used for Android, just run it again once the `ios` platform exists so it picks up that target too. Confirm the source icon (`icon-original.png` or whatever the current source asset is) is passed the same way it was for Android.

3. **Sync**
   ```
   npx cap sync ios
   ```

4. **Signing**
   - Apple Developer account needed for device testing / TestFlight / App Store (not needed for simulator-only testing).
   - Bundle ID: `com.frontline.app` (matches Android's `appId` in `capacitor.config.ts`).
   - In Xcode: select a signing team, let Xcode manage the provisioning profile.

5. **Location permission**
   The app uses browser-based geolocation (no native Capacitor Geolocation plugin installed), but iOS WebKit still requires a usage-description string. Add to `ios/App/App/Info.plist`:
   ```xml
   <key>NSLocationWhenInUseUsageDescription</key>
   <string>Frontline uses your location to show nearby campaigns and territory.</string>
   ```

6. **OAuth deep-link (Associated Domains)**
   Android's App Links equivalent. Currently blocked on Android too (the `assetlinks.json` at `https://www.frontlinemaps.com/.well-known/assetlinks.json` is still a placeholder pending a release keystore fingerprint) — same underlying blocker applies here:
   - Add the Associated Domains capability in Xcode (`applinks:www.frontlinemaps.com`).
   - Host `https://www.frontlinemaps.com/.well-known/apple-app-site-association` with this app's Team ID + bundle ID.
   - Until that file exists, the OAuth-return redirect back into the app won't verify on iOS, same as Android currently.

7. **Test**
   ```
   npx cap open ios
   ```
   Run in the simulator. Same `CAP_DEV_SERVER` env var flow as Android — `scripts/dev.mjs` should point the iOS build at your local dev server the same way, but confirm it once `ios/` actually exists (it's never been tested against iOS since the platform doesn't exist yet).

8. **Later, for store submission**
   - App Store Connect record.
   - TestFlight for beta testing.
   - Apple's privacy nutrition labels (`NSPrivacyAccessedAPITypes` manifest) — required even for a WebView wrapper if any tracked API categories are touched (e.g. UserDefaults, disk space).

## Suggested order

Do steps 1-3 and 7 (simulator) before enrolling in the paid Apple Developer program ($99/yr) — that only becomes necessary at step 4 for device testing or anything beyond the simulator. Confirm the WebView wrapper behaves correctly on iOS first.

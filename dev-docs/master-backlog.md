- [ ] **HIGH PRIORITY — Lock down FastAPI/Railway backend auth** (noted 2026-08-12) — discovered while fixing a prod bug where the "Download my data" link pointed straight at the Railway backend URL (cross-origin `<a download>` was ignored by the browser, causing a raw navigation to a backend error page). Root cause of that specific bug is fixed (`frontend/src/app/api/account/export/route.ts` now proxies same-origin, resolving the user id from the session). But it surfaced a broader pattern: backend routes like `GET /api/account/{user_id}/export` and `DELETE /api/account/{user_id}` trust whatever `user_id` is in the path with **zero auth check of their own** — they rely entirely on the Next.js layer to only ever call them with the verified caller's own id. There's currently no defense-in-depth: if the Railway URL structure is ever hit directly (leaked link, guessed UUID, bug in a route handler that forwards the wrong id), it's a live IDOR/PII exposure. Needs a real fix — e.g. verifying a forwarded Supabase session/JWT on the backend itself, or a shared secret between the Next.js layer and FastAPI — not just trusting the frontend to always gate correctly.
